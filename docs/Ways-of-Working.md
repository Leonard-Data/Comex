# Ways of Working

## Three places, one rule each

| Place | Holds | Rule |
|---|---|---|
| **Wiki** | Business context, decisions, app definitions | If someone would ask "why" or "what does this mean", it goes here |
| **Project board** | Roadmap + project placeholders | Every project has an app, a phase and a target date |
| **Issues** | Solution traces and access issues | One issue per symptom or request, labelled |

## Labels

- `access` — access requests and access failures
- `solution-trace` — symptom → root cause → resolution
- `ecosystem` — changes to an app or an integration
- `business-context` — wiki needs updating

## Board fields

**App**, **Phase** (Idea / Scoping / Build / UAT / Live), **Owner**, **Target date**, **Status**.
The **Roadmap** view is grouped by App and spans Target date. The **Projects** view is the flat table.
